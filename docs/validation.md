# Фактическая проверка решения

Проверено в текущей облачной среде на CPU. GPU и удалённое выполнение в Kaggle
**не проверены**: в текущей среде нет Kaggle API-токена и применённого сетевого
разрешения для Kaggle. Notebook можно импортировать и выполнить вручную в Kaggle
без передачи токена в код.

## Обучение

- Python 3.12.14, PyTorch 2.9.1+cpu, NumPy 2.3.5; полный состав —
  `docs/cpu-environment.txt`.
- Процедурный набор `data/procedural_v1`: 96/16 изображений-четвёрок train/validation;
  seed 2026. Каждая четвёрка содержит четыре PNG/L/128×128.
- 6 оптических слоёв, CNN width=12, batch=4, Adam lr=0.005, 24 эпохи, seed=42,
  2 CPU-потока, cosine scheduler.
- Validation loss до обучения: **0.9402181**; лучший: **0.9188025**, эпоха 24.
- Обучение заняло около **140 секунд** в этом запуске. Веса действительно
  обновлены; величина изменения параметров и полная история есть в `training.json`.
- Сеть с обучаемым over-relaxation выбрана по validation. Ранний вариант
  использовался для разработки; его тестовые результаты не выдаются за финальную
  независимую оценку. Данные ниже — новая выборка с другим seed.

## Независимая финальная выборка

`data/independent_holdout`, seed **91007**, 32 новых четвёрки. Эта выборка не
использовалась для обучения и выбора checkpoint. В manifest сохранены seed и
SHA256; в `benchmark.json` — результаты каждой четвёрки. Показатели усреднены
по четырём плоскостям и затем по 32 четвёркам.

| Метод | Pearson ↑ | SSIM ↑ | мс/четвёрку ↓ |
|---|---:|---:|---:|
| FresnelNet, обученная | 0.59643 | 0.09554 | 43.03 |
| Та же сеть до обучения | 0.58689 | 0.09028 | 44.61 |
| GS, 6 шагов | 0.58689 | 0.09028 | 25.94 |
| GS, 80 шагов | 0.61833 | 0.12444 | 158.99 |

Измерение времени — один проход после прогрева, batch=4; это batched throughput,
не latency одиночного запроса и не статистическая оценка производительности.
Загрузка PNG, обучение, расчёт метрик и запись результатов исключены из времени
синтеза. Округление phase/amplitude в 8 бит включено в качество всех методов.

Обучение даёт умеренное улучшение относительно такой же сети до обучения и GS
с тем же числом шагов. GS за 80 шагов качественнее, но медленнее в данном CPU-прогоне.
**Преимущество по качеству над классическим методом не заявляется.** Малый SSIM
и видимые помехи означают, что это рабочая исходная реализация, а не решение с
гарантированно высоким качеством. Для соревнования нужны проверка на реальных
изображениях, расширение обучающего набора и дальнейшая настройка.

Использована первая четвёрка независимой выборки, `test/sample_0000`, а не отобранный
лучший пример. Исходные PNG, ДОЭ и реконструкции находятся в `run/result` архива.

Среднее: Pearson **0.59015**, SSIM **0.09572**. PNG амплитуд масштабированы по

## Что прошло

- **8 тестов pytest**, 0 пропущенных: прямая квадратура дифракции без FFT,
  сопряжённость, сохранение физической мощности на разных сетках, finite-difference
  градиент фазы, градиенты CNN, кодирование фазы, Pearson/SSIM, строгие PNG,
  воспроизводимые данные, реконструкции сохранённого квантованного ДОЭ.
- Все **6 исполняемых ячеек** автономного notebook выполнены локально через Jupyter.
  Для этой интеграционной проверки включён `DOE_QUICK_CHECK=1`: 8/4/4 примера,
  2 эпохи, 2 слоя, width=4. Проверены обучение, benchmark, экспорт изображений и
  сборка ZIP. Это **не** проверка полной GPU-конфигурации notebook в Kaggle.
- Полное обучение основной CPU-модели и оценка 32 новых четвёрок выполнены отдельно
  от короткого notebook-прогона.

## Что остаётся

В исходных DOCX/PDF нет четырёх PNG объектов организаторов: результаты выше
относятся только к процедурной демонстрации. Для выполнения на нужной четвёрке
передайте её в `doe predict` или `INPUT_IMAGES` notebook. Код не подменяет и не
дорисовывает официальные входы.

Для автоматического запуска в аккаунте `fiskarik` требуются защищённый
`KAGGLE_API_TOKEN` и разрешённый сетевой доступ. Настройки сохранены в черновике
среды ранее; их сохранение и публикация не подтверждают выполнение в Kaggle.
Экспериментальная проверка оптики на физическом ПВМС не проводилась.
